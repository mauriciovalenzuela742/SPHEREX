# AGENTS.md — 本仓库中给智能体的指令

本文件是**唯一来源**。`CLAUDE.md` 和 `GEMINI.md` 指向这里,只补充各工具特有的内容。
如果你纠正了什么,请在这里纠正。

---

## 1. 我们在构建什么

为 NASA Space Apps 2026 的挑战 *Planet X and SPHEREx* 构建一个**公开的网页工具**。
用户输入 RA/Dec;工具以一段小视频的形式展示该天区 SPHEREx 图像的时间序列,
以便凭肉眼看出什么在移动或亮度在变化。

挑战的完整文本在 `docs/00_DESAFIO.md` 中。**在提出架构之前先读它。**
智能体常常会假定这是一个用视频模型做分类的问题:
并不是。被评判的交付物是查看器。

## 2. 不可协商的规则

1. **不要编造数据、endpoint、参数或结果。** 如果你没有验证过,就说:「我没有验证」或「根据 IRSA 的文档,
   我没有打开过」。一个编造的 endpoint 会让人在凌晨 3 点多花一小时调试。
2. **验证产物,而不是报告。** 在说某件事可以运行之前:打开 URL,查看
   FITS,数一数历元,把位置与 SIMBAD 比较。一个 `200 OK` 并不能证明图像
   是正确的那块天空。
3. **空结果不能证明某物不存在。** 如果一次查询什么也没返回,在得出「那里没有数据」的结论之前,
   先试另一个集合、另一个半径、另一个历元。
4. **没有来源就没有数字。** 每一个会进入 README、pitch 或界面的数字,
   都必须能够打开并核实。把链接或文件放在旁边。
5. **不要向 `main` 提交。** 在你自己的分支上工作。见 `CONTRIBUTING.md`。
6. **不要把 FITS 下载到仓库里。** 它们放在 `data/cache/`,该目录在 `.gitignore` 中。
   一个 SPHEREx 的 MEF 大约 70 MB。
7. **不要对外发布任何东西**——部署到公共域名、发到社交网络、发送
   邮件、在他人的仓库中提 issue——除非有人明确批准。
8. **活动规则:** 黑客松于 2026年11月14日 10:00 开始;在此之前不得编写
   解决挑战的代码。见 `docs/08_REGLAS_DEL_EVENTO.md`。

## 3. 已确定的技术栈

| 层 | 选择 | 原因 |
|---|---|---|
| 后端 | Python 3.11 + FastAPI + uvicorn | `astropy`/`pyvo`/`astroquery` 只存在于 Python |
| 数据访问 | `pyvo`(SIA2)以及对 IRSA cutout 服务的直接 HTTP | 这是 IRSA 文档记载的途径 |
| 图像 | `astropy.io.fits`、`astropy.wcs`、`astropy.visualization` | 社区标准 |
| 前端 | React + Vite + TypeScript | 搭建快,团队熟悉 |
| 天空 | 基于 IRSA 的 HiPS 立方体的 Aladin Lite 3.8.2(版本固定);Gaia 和 SIMBAD 使用 Harvard 镜像 | 无需自己编写即可解决天空背景和叠加层 |
| 缓存 | 本地磁盘(`data/cache/`),可选 Redis | cutout 很慢;没有缓存,演示就会垮 |
| 部署 | 前端在 Vercel(只有 Mauricio 有访问权限);后端待定(ADR-001) | 见 `docs/03_ARQUITECTURA.md` |

这一决定记录在 `docs/adr/ADR-001-stack.md` 中。**不要擅自更改。** 如果你认为它
是错的,请写一份新的 ADR 并向团队提出。

## 5. 如何在这里工作

**编写代码之前**

- 阅读 `docs/` 中涵盖你负责部分的文档。它们的写法是为了让你不必读完
  整个 IRSA 文档。
- 如果任务涉及 SPHEREx 数据,skill `spherex-datos` 中有已对照官方文档核实过的 endpoint、波段和文件
  结构。

**工作期间**

- 小而可验证的改动。活动进行到一半时不要大规模重写。
- 每个涉及天球坐标的函数都带有一个使用 `data/campos_de_prueba.yml` 中某个天区的测试。
- 如果某件事花了你超过 30 分钟却没有进展,**停下来并说出来**。在黑客松中,
  硬撑的代价高于换一种思路的代价。

**完成时**

- 说明你验证了什么以及如何验证。不是「可以运行」,而是:「我打开了 `/api/epochs?ra=...&dec=...`,返回了
  2025-05 到 2026-10 之间的 14 个历元,我把第一个与 IRSA 的 Data Explorer 比较,结果一致」。
- 说明你**没有**验证什么。这同样重要。

## 6. 如何汇报

- 先给结论,再给细节。
- 报告问题时要附带解决办法或你推荐的方案,而不是只给出错误。
- 当你面对的是不了解细节的人时,不要使用内部行话、提交哈希或长路径。
- 如果你失败了,就说出来。一个带着错误却没有警告就交付的成果,比说明某事失败更糟。

## 7. 最小术语表

让没有天文背景的智能体不至于写出荒唐的东西。

- **RA / Dec** — 赤经和赤纬,即天球坐标。RA 以时(`08h55m10.831s`)或度(0–360)表示;Dec 以度表示(−90 到 +90)。**把时和度弄混
  是最常见的错误**:两者之间差一个 15 倍的因子。
- **历元** — 在给定时刻的一次观测。那段「小视频」就是同一片天区在
  不同历元的画面,按时间排序。
- **指向 / 扫描轮次** — 一个指向是望远镜的一个位置(天空的某个位置在每个指向中落入 2
  个文件:D1+D4、D2+D5、D3+D6 对);一个扫描轮次是对天空的一次完整扫描
  (1-6 周,扫描轮次之间间隔约 6 个月)。**一个扫描轮次不是一个历元**:对于视频,单位是
  扫描轮次(`docs/09`)。
- **自行** — 恒星在天空中的视位移,单位是毫角秒每年(mas/yr)。正是它使得近距离恒星在各历元之间移动。
- **视差** — 由地球绕太阳运动引起的视摆动。周期为一
  年;它给出距离。
- **FITS** — 天文图像的标准格式。**MEF** 是在同一个文件中带有多个扩展
  (图像、方差、flags 等)的 FITS。
- **WCS** — FITS 头中把像素 ↔ 天球坐标相互转换的信息。
- **Cutout** — 围绕某个位置从大图像中裁出的一块。
- **HiPS** — CDS 的分层图块格式,使得可以在浏览器中浏览整个天空。
  它是 Aladin Lite 所使用的格式。
- **LVF** — 线性可变滤光片。SPHEREx 的光学技巧:波长沿探测器的一个轴
  变化,因此源在图像中*落在哪里*就决定了它是在*哪个
  波长*下被测量的。实际后果:同一片天区的两幅图像,如果是在不同波长下拍摄的,
  就可能无法比较。
- **褐矮星** — 介于行星和恒星之间的天体。冷、红、在红外中明亮:
  正是 SPHEREx 看得好、也是 Backyard Worlds 志愿者要找的东西。
