# 06 — 评审团、奖项与 pitch

---

## 如何评审

Space Apps 的漏斗是：本地活动的评审团选出 **Global Nominees** → NASA 及合作机构的专家选出 **Global Finalists** 和荣誉提名 → 一个执行委员会选出 **10 个 Global Winners**。

也就是说：**第一道筛选是本地评审团**，每个团队的时间很少，而且不会阅读代码。之后才是真正懂天文学的 NASA 人员。项目必须在两种场合下都能成立：在两分钟内打动人，并经得起专家的审视。

在圣地亚哥的活动中，公布的形式是 **2 分钟 pitch + 2 个问题**。

## 十个全球奖项，以及哪些是我们的

| 奖项 | 是我们的吗？ |
|---|---|
| **Best Use of Data** | **是，主要目标。** 字面上就是“让空间数据可及”。挑战要求的正是这个 |
| **Best Use of Science** | **是。** 把光谱轴展示好，并用 Gaia 验证，就是看得见的科学方法 |
| **Best Use of Technology** | 有可能，如果查看器在技术上引人注目（浏览器中的 102 个波段） |
| **Galactic Impact** | 有可能：规模化的公民科学 |
| **Best Use of Storytelling** | **是，如果我们认真做。** 冥王星的故事和闪烁比较器就在那里等着我们取用 |
| **Most Inspirational** | 有可能，与上一项相关 |
| **Global Connection** | 有可能，如果我们使用合作机构（CSA/NEOSSat）的资源，并把查看器设想为共享基础设施 |
| Best Mission Concept | 不是。我们不提出任务 |
| Art & Technology | 不是，除非查看器在视觉上很出众 |
| Local Impact | 较弱，除非我们把它与智利天文学联系起来 |

**瞄准两三个，而不是十个。** Best Use of Data 和 Best Use of Science 是自然的选择；如果 N 从第 0 小时起就打磨叙事，storytelling 一项是白拿的。

## 挑战的八条要点就是评分标准

*Potential Considerations* 是挑战作者期望看到的东西。每满足一条，就是一个 NASA 评委会认可的得分点。

| 挑战要点 | 我们如何满足 | 成本 |
|---|---|---|
| 易于随新的 releases 更新 | SIA2 集合通过配置而不是写死 | 低 |
| 创造性地展示 102 个波段 | 波段选择器 + HiPS 立方体 | **中，且这是差异化所在** |
| 对不同历元的图像做加减 | `mode=diff_first` / `diff_prev` | 低 |
| 可选择的视场 | 参数 `size` | 极低 |
| 叠加 Gaia 或 WISE | Aladin Lite 中的星表 overlay | 低 |
| URL 中的坐标 | `?ra=&dec=&...` 反映状态 | 极低 |
| 显示诸如污染 flags 之类的元数据 | MEF 的 `FLAGS` 扩展 | 低 |
| 使用公开工具（Astropy、Aladin） | 它们就是技术栈 | 零 |

八条中有七条是低或极低成本。**必须全部满足。** 在 [`05_PLAN_24H.md`](05_PLAN_24H.md) 中按处理顺序列出了它们。

## 2 分钟的 pitch

结构。时间是大致的，但顺序不容商量：**演示先于解释**，因为如果被打断，至少他们已经看到了工具。

**0:00 – 0:20 · 开场**

> 1930 年，Clyde Tombaugh 通过观察同一片天空的两张照片，发现其中一个点移动了，从而发现了冥王星。如今，SPHEREx 每六个月以 102 种红外颜色拍摄整个天空，而没有人这样去看它。

**0:20 – 1:10 · 现场演示**（占一半时间；这是被评判的部分）

1. 输入 `WISE 0855`。输入名称，而不是坐标：证明它适合任何人。它是必选案例（组织方的测试天体之一），始终展示。
2. 点播放，然后做第一帧 − 最后一帧的减法。**褐矮星在移动**（整个时段约 1.3 px）：一对红/蓝。要诚实地说明，在单次曝光中它显得很暗，而按扫描轮次求和会改善这一点。然后是 **eps Ind B**，其运动看得最清楚（实测 −0.85/−0.71 px，预测 −0.92/−0.57 px）。
   对于 WISE 0855，计划有两项补充：CatWISE2020 的 overlay（它不在 Gaia 中，而 CatWISE 带有它的自行；负责人 V2 Juan Pablo；**已在分支 `v/v2-catwise` 中完成，待 PR**：在从 SIMBAD 传播的位置 2.6″ 处标出 WISE 0855），以及以 1/VARIANCE 为权重的按扫描轮次求和（负责人 D2 Bryan；`docs/10` 和 `docs/09`；**待办**）。挑战指南看重叠加 Gaia 和 WISE。在它们进入 `main` 之前，不要把它们作为已部署查看器的一部分来展示。
3. 移动波段选择器。同一片天区，在另一个波长下。
4. 在 Barnard 或 eps Ind B 上打开 Gaia 的 overlay（WISE 0855 不在 Gaia 中：它的 overlay 是 CatWISE2020）。这些点落在它们该在的位置。*“这就是我们知道它是正确的原因。”*
5. 复制 URL。*“这是可分享、可嵌入的。”*

**1:10 – 1:35 · 为什么重要**

> 已知的大多数褐矮星和彗星，都是志愿者通过观看图像闪烁发现的。这个社区存在，而如今他们没有办法查看 SPHEREx。被引用最多的 Planet Nine 候选体，来自对两次相隔一段时间的红外巡天的比较：同样的技术。我们把它向任何人开放，并带有 102 个波段的光谱轴（据我们所能核实，没有任何公开工具在同一块屏幕上把它与时间 blink 结合起来）。

**1:35 – 2:00 · 我们构建了什么，以及接下来是什么**

用一句话说明技术栈，DR1 的真实数据——本月发布——公开 URL，开源代码。再加一句接下来是什么。

### pitch 的规则

- **绝不针对冷查询进行现场演示。** 五个天区都已预热。
- **视频在另一个标签页中准备好。** 如果 wifi 失败，就播放视频，不要道歉。
- **不要说“可以”。** 展示已有的东西。没有的，就把它称为接下来要做的。
- **不要承诺发现了任何东西。** 有天文学家的评审团会立刻惩罚这一点。
- 如果还有时间，**就还给他们**。在 1:50 把所有东西展示完，比在 2:10 手忙脚乱要好。

## 令人不舒服的问题及其回答

**“IRSA 的 Data Explorer 不是已经做了这个吗？”**
对这类受众来说不是。Data Explorer 是给天文学家用的档案库：你得知道要请求哪个集合、MEF 是什么、图像如何拉伸。我们解析名称、按历元分组、归一化，并交付闪烁。这就是档案库与查看器之间的区别，也正是让 WiseView 相对于 WISE 档案库变得有用的同一个区别。

**“我怎么知道这图像就是我请求的那个坐标的？”**
通过 Gaia 的 overlay：我们绘制 Gaia 预测该日期的位置，它们落在图像的源上。*（并且在屏幕上展示。）*

**“你们为什么没有用机器学习？”**
因为挑战要求的是面向人的查看器，也因为真正的瓶颈是获取并对齐正确的数据，而不是识别运动。AI 在这里的贡献在于用针对裁切图的小型网络筛选候选体——ALeRCE broker 对 ZTF 警报所做的——我们把它作为下一步提出。*（详见 [`01_ESTADO_DEL_ARTE.md`](01_ESTADO_DEL_ARTE.md) §6。）*

**“如果我输入一个没有数据的坐标会怎样？”**
*（输入一个并展示空状态，它会说明有多少个历元，并建议一个附近的天区。）*

**“这能扩展到整个天空吗？”**
查询是通过 SIA2 按位置进行的，所以在覆盖范围上可以。没有基础设施就无法扩展的是缓存：如今我们预热天区；在规模化时需要预先计算裁切图，而这正是 unWISE 为 WiseView 所做的。

**“光谱有多准确？”**
它们只是示意性的，是扣除黄道光的孔径测光，并且我们在界面本身就这样说明。要做科学研究，有 IRSA 的 Spectrophotometry Tool。*（永远不要说它们达到科学级质量。在这里诚实加的分比减的多。）*
