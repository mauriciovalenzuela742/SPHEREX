# 09 — EDA：真实数据告诉我们的（2026 年 11 月 14 日）

用 IRSA 的数据对第 1 小时检查清单（[`02_DATOS_SPHEREX.md`](02_DATOS_SPHEREX.md) §9）的回答。
每个数字都来自 [`../eda/resultados/`](../../../eda/resultados/) 中的某个文件或
[`../eda/figuras/`](../../../eda/figuras/) 中的某张图；生成它们的脚本位于 [`../eda/`](../eda/README.md)，
可以重新运行。

## 十行摘要

1. **数据绰绰有余。** 每个测试天区有 258 到 2,514 个文件，3–4 次天空扫描，
   **1.0 到 1.4 年的时间基线**。必须查询 **DR1 和 QR3**：文件不重复，
   而且 QR3 带有最新的扫描（WISE 0855 除外，它还没有 QR3）。
2. **整个时段内的运动是 1–2 个像素**，而不是一次跳变。像素尺度 6.15″
   （在 SIA2 中确认），PSF 为 7.5–8.7″。Barnard：1.8 px；WISE 0855：1.3 px；eps Ind B：1.1 px。
3. **运动是可以测量的，在不饱和的恒星上。** 在 eps Ind B 上，质心在 2025.31 到 2026.74 之间位移
   −0.85 / −0.71 px（西 / 北）；SIMBAD 预测为 −0.92 / −0.57 px。
   明亮的恒星（Barnard、RW Aur）会**饱和**：其核心被标记为坏像素，相减显示出
   一对红/蓝，**即使它们没有移动**（RW Aur）。对它们只有定性结论有效。
4. **天体的 λ 在文件之间会跨越整个探测器的宽度**（同一个探测器内约 16 个带宽）。
   不让它匹配的 blink 会混入 16 种不同的“颜色”。
5. **但让它匹配很容易：** 在每个天区和探测器中，有几十对历元具有相同的 λ
   （在半个带宽之内）。采用“λ 匹配”选择后，离散度从 0.47 µm 降到
   0.005–0.04 µm。
6. **无需下载文件即可算出 λ：** `WCS-WAVE` 表对每个探测器是固定的，
   IMAGE 的头可以通过 HTTP Range 请求下载（约 35 KB）。约 1,900 个文件用时约 2.5 分钟。
7. **取向在两次扫描之间旋转约 180°。** 在 blink 或相减之前，必须**重投影到公共网格**（北向上）。
   没有这一步，相减比较的就是不同的天区。
8. **一个 cutout 中位数需要 7 s（p90 为 11 s，最大 29 s），无论多大尺寸都重约 3.9 MB**：
   几乎全是 PSF 扩展，它是整个带来的。出现过瞬时的 503 错误。**没有缓存就没有演示。**
9. **IRSA 不返回 CORS**：浏览器无法直接向它请求任何东西。**一切都经过
   后端**，包括 SIA2。
10. **DR1 立方体有两个版本。** SIA2 提供的版本（`spherex_dr1_cube`）是
    每个瓦片约 320 MB 的 FITS，cutout 服务会拒绝它们。**HiPS 版本可以在 Aladin 中加载**
    （`irsa.ipac.caltech.edu/data/hips/SPHEREx/spherex_allsky_cube`：PNG 瓦片，102 个平面，CORS
    开放），并且已经在部署的查看器中。它们是用于可视化的 PNG：不提供光谱所需的流量。
    *11 月 14 日下午的更正：本文档的第一版说立方体不能用于 Aladin，
    因为当时只测试了 SIA2 的版本。*

## 1. 各天区清单

来源：`eda/resultados/inventario.json`，SIA2 搜索，半径 0.01°，位置为传播到
2025-11（MJD 61000）的位置。

| 天区 | DR1 | DR1 deep | QR3 | QR3 deep | 指向次数 | 扫描 | 首次 → 末次 | 基线 |
|---|---|---|---|---|---|---|---|---|
| WISE 0855 | 258 | 0 | 0 | 0 | 129 | 3 | 2025.34 → 2026.37 | 1.02 a |
| Barnard | 240 | 0 | 124 | 0 | 185 | 3 | 2025.62 → 2026.73 | 1.10 a |
| eps Ind B | 347 | 0 | 120 | 0 | 245 | 4 | 2025.31 → 2026.75 | 1.44 a |
| RW Aur | 226 | 0 | 110 | 0 | 168 | 3 | 2025.67 → 2026.71 | 1.04 a |
| R Dra | 422 | 1,233 | 126 | 733 | 1,273 | 连续 | 2025.31 → 2026.74 | 1.42 a |

关于这张表需要知道的：

- **每次指向给出 2 个文件**，一个短波、一个长波，总是成对
  **D1+D4、D2+D5、D3+D6**（二向色镜分光；同一片天区落在两个探测器上）。
- **一次扫描不是一个历元**：持续 1 到 6 周，包含 7–20 次访问和约 50–60 次指向，
  每次处于不同的 λ。对视频来说，自然的单位是**扫描**（3–4 帧），或者
  如果想要更多帧，则用访问，代价是混入不同的 λ。
- **R Dra 位于深场**（靠近黄道北极）：几乎是连续观测。
  它是用来测试光变曲线的天区，不是典型的。
- 所有被查询的文件都有 `L2DQAFLG = Pass`（2 级质量控制）。

## 2. 波长（线性可变滤光片）

来源：`eda/resultados/lambda_resumen.json`、`lambda_por_archivo.csv`，图 `01_lambda_vs_tiempo.png`。

- 在同一个探测器内，随着文件不同，天体的 λ 会跨越探测器的**整个**范围：约 16 个带宽。
  示例 WISE 0855，D5：从 3.82 到 4.41 µm。
- 在每次扫描中，SPHEREx 都会让天体再次经过滤光片，所以**每个 λ 大约每 6 个月重复一次**。
  相隔超过 0.4 年且 λ 相同的历元对：每个天区和探测器有 18 到 196 对。
- 验证：`WCS-WAVE` 的自有插值在 6 个探测器上与 astropy（`WAVE-TAB`）一致，
  直到小数点后第四位。

WISE 0855、D5 的直接比较（图 `02_wise_0855_*.png`）：

| 选择方式 | 4 帧的 λ（µm） | 离散度 |
|---|---|---|
| 朴素（每次扫描的第一个文件） | 4.295 · 3.821 · 4.047 · 3.835 | **0.474 µm** |
| λ 匹配 | 4.145 · 4.153 · 4.153 · 4.180 | **0.035 µm** |

## 3. 几何：取向和对齐

在 25 个 `size=0.1` 的裁切图（59×59 px）上测得：

- 探测器的位置角：在 ~−160° 与 ~+19° 之间交替（WISE 0855），~−179° 与 ~+1°
  （Barnard），~−28° 与 ~+154° 之间（eps Ind B）。靠近极点（R Dra）时，角度是任意的。
- 裁切图的尺寸在文件之间变化 ±1 px（58 或 59）。

**后果：** 后端将每个裁切图重投影到一个公共的 TAN 网格，北向上，采用原生尺度
（`reproject` 库的 `reproject_interp`）。实现于
`eda/03_recortes_y_figuras.py`（`grilla_comun`、`panel`）。

## 4. 每个天区能看到什么

图 `eda/figuras/02_*.png`。0.1° 的裁切图，`IMAGE − ZODI`，已重投影，asinh 拉伸。
橙色圆圈是用 SIMBAD 的自行传播到每个文件日期的位置。

| 天区 | 波段 | 能看到天体吗？ | 能看到变化吗？ |
|---|---|---|---|
| Barnard | D2（1.5 µm） | 能，**饱和**：核心 49 个像素中有 30–44 个被标记为坏像素 | 红色在上 / 蓝色在下的一对（朝北，与它的运动一致），但无法测量：核心被掩膜后质心不存在 |
| eps Ind B | D5（3.86 µm） | 能，未饱和 | **能，而且测到了**：−0.85 / −0.71 px，预测为 −0.92 / −0.57 px（见下文） |
| RW Aur | D3（1.94 µm） | 能，饱和（核心有 6–8 个坏像素） | **即使不动也有红/蓝一对**：这是饱和和掩膜的效应，不是运动 |
| R Dra | D4 | 能 | 待测量亮度 |
| WISE 0855 | D5 和 D6 | 在单次曝光中**几乎看不到** | 单次曝光中看不到 |

**WISE 0855 是必选案例（组织方的测试天体），总是要展示，但在单次曝光中看起来很暗**：每次曝光都太暗。要看到它，
需要把每次扫描的曝光相加（挑战的要点
«add together all the data taken by each of the six detector arrays»）。

### 质心：测得的位移是 SIMBAD 预测的位移吗？

来源：`eda/resultados/centroides.json`（`eda/05_centroides.py`）。λ 匹配的第一个和最后一个历元，
重投影到同一网格；坏像素已排除。x 为正表示西，y 为正表示北。

| 天区 | 测得（px） | 预测（px） | 场星（中位数，px） | 核心中的坏像素 |
|---|---|---|---|---|
| eps Ind B | −0.85 / −0.71 | −0.92 / −0.57 | +0.05 / −0.37（3 颗恒星） | 49 个中的 1 和 0 |
| RW Aur | +0.73 / +1.22 | 0 / 0 | −0.01 / +0.07（5 颗恒星） | 49 个中的 6 和 8 |
| Barnard | 无法测量（核心为空） | +0.14 / +1.81 | −0.14 / +0.04（8 颗恒星） | 49 个中的 44 和 44 |

解读：

- **对齐是有效的：** 场星的位移为十分之一到十分之二像素（在 eps Ind B 中最大
  0.37 px，仅有 3 颗恒星）。
- **eps Ind B 的移动量正是它应该移动的量**，每个轴上在约 0.15 px 之内。这是
  λ 匹配 + 重投影 + 相减能显示真实运动的定量证明。
- **饱和的恒星会骗人。** Barnard 和 RW Aur 的核心被标记为坏像素
  （OVERFLOW、TRANSIENT、SUR_ERROR）。排除它之后，剩下的是一个不对称的环，
  质心会偏移：RW Aur 在没有移动的情况下“移动”了 1.4 px。相减中出现的
  红/蓝对与真正移动的天体留下的相同。**当天体饱和时，查看器必须发出提醒。**

## 5. 质量掩膜（`FLAGS`）

位的名称**就在 `FLAGS` 本身的头中**（卡片 `MSKNnnnn` 名称，
`MSKMnnnn` 掩膜，`MSKDnnnn` 描述）：不需要去查补充材料中的表 16。

25 个裁切图中的频率：

| 位 | 名称 | 像素 % | 是否使像素无效？ |
|---|---|---|---|
| 21 | SOURCE | **72.4 %** | **否**：标记有已知的源。这正是我们想看的 |
| 28 | HALO | 2.1 % | 有争议：亮源周围的瞬时晕 |
| 0 | TRANSIENT | 1.6 % | 是 |
| 2 | SUR_ERROR | 1.3 % | 是 |
| 26 | BLOOM | 0.8 % | 有争议 |
| 19 | OUTLIER | 0.7 % | 是 |
| 6 | NONFUNC | 0.4 % | 是 |
| 17 | PERSIST | 0.3 % | 是 |
| 1 | OVERFLOW | 0.2 % | 是 |
| 11 | COLD | 0.1 % | 是 |

**陷阱：** `FLAGS != 0` 会因为 SOURCE 而标记裁切图的 72 %。必须使用按位
掩膜。EDA 使用的掩膜（`eda/03_recortes_y_figuras.py` 中的 `BITS_MALOS`）遮盖约 4 % 的
像素，但在用双线性插值重投影时 NaN 会扩大，在屏幕上显示为
白色方块（约 15 %）。对查看器来说，最好是**用最近邻重投影掩膜并填补**
坏像素，并将掩膜显示为可选图层。

## 6. 基础设施

来源：`eda/resultados/infraestructura.json`、`latencia_cutouts.json`。

| 问题 | 回答 | 后果 |
|---|---|---|
| IRSA 返回 CORS 吗？ | **不**（SIA2 和文件都不行） | 一切都经过我们的后端 |
| SIA2 查询 | 每个集合 1–3.5 s | 可以实时进行，4 个集合并行 |
| 通过 HTTP Range 取头 | 约 2 s，35 KB；6 个并行时有效约 0.1 s | 数百个文件的元数据和 λ 只需几秒 |
| Cutout `size=0.1` | 中位数 7.3 s，p90 10.8 s，最大 29 s；约 3.9 MB；4 线程 52 s 内完成 25 个 | 磁盘缓存是必需的；预热演示用的天区 |
| 更小的 cutout 会更快吗？ | 不会：0.02° 同样重（PSF 是整个带来的） | 始终请求 0.1°；更大也不会更贵 |
| 错误 | 瞬时的 503；有一次连续重试 4 次仍然失败 | 带等待的重试，以及 UI 中的错误状态 |
| 通过 SIA2 的 DR1 立方体（`spherex_dr1_cube`） | FITS 512×512×102，每个瓦片约 320 MB，像素 12.9″；cutout 响应 422 “lacks WCS”（第二次测试为 503） | 不适用于裁切，也不适用于即时光谱 |
| **HiPS 形式的 DR1 立方体**（`/data/hips/SPHEREx/spherex_allsky_cube`） | `properties` 返回 200，带 `Access-Control-Allow-Origin: *`；PNG，order 5，102 个平面（第 50 和 51 个为空），像素 12.9″，发布于 2026 年 11 月 1 日 | **能在 Aladin 中加载**（部署的查看器正在使用它）。它是所有历元的马赛克：没有时间轴，且是 PNG，没有流量 |
| CDS 上的 SPHEREx HiPS | MocServer 列出 `CDS/P/SPHEREx/QR2/D1`…`D6`（QR2，order 7）；`alasky` 在 11 月 14 日连 DSS 都返回 404 | 如果 IRSA 的失败，则作为 B 计划；未验证 |

## 7. 未验证的内容

- 亮度：在任何天区都没有测光（RW Aur 和 R Dra 的变光未测量）。
- CDS 的 HiPS 能否在 Aladin Lite 中加载（测试时服务器宕机）。现在已不再需要：IRSA 的可以加载。
- `_deep` 集合没有用于 λ 分析（只用了 DR1 和 QR3）。
- 如何测量饱和恒星的位置（对翼部做 PSF 拟合，或使用不会饱和的探测器）。
- 把一次扫描的曝光相加以看到 WISE 0855。
- R Dra 的相减没有详细检查。质心只在第一个和最后一个历元上测量。
